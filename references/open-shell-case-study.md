# 案例：MaaHappyFish「开贝壳」任务

这个案例用于展示本 Skill 如何从人工规则发展成正式状态机。

## 1. 用户业务规则

起点：活动初始页。

人工流程：

```text
点击「立即开始」
→ 点击「打开贝壳」
→ 普通奖励时始终选择「继续开贝壳」
→ 遇到章鱼时固定选择左侧“保留一个随机奖品”
→ 本轮结束后点击「太好了」
→ 回到活动初始页
```

业务参数：

```text
开贝壳次数 = N
```

“一次”的定义不是“开一个小贝壳”，而是完整执行上面整个闭环并重新回到活动初始页。

---

## 2. 第一轮实机探索

标准化坐标系：

```text
1280 × 720
```

主要状态：

| 状态 | 识别文字 | bbox | 推荐 ROI |
|---|---|---|---|
| A 初始页 | 立即开始 | [505,605,270,60] | [450,560,380,130] |
| B 打开贝壳 | 打开贝壳 | [505,615,270,65] | [450,570,380,130] |
| C 普通奖励 | 继续开贝壳 | [720,620,270,65] | [650,570,380,130] |
| D 章鱼 | 保留一个随机奖品 | [310,620,270,65] | [250,570,380,130] |
| E 结算 | 太好了 | [505,615,270,65] | 初始 [450,570,380,130] |

第一轮实际路径：

```text
A
→ B
→ C
→ C
→ C
→ D
→ E
→ A_return
```

---

## 3. 状态机修正：C 不会回到 B

第一版设计曾误以为：

```text
C 继续开贝壳
→ B 再次点“打开贝壳”
```

实机发现并不是这样。

真实情况：

```text
C 点击“继续开贝壳”
→ 自动播放下一枚贝壳动画
→ 直接进入下一结果状态
```

因此正式结构采用 ResultRouter：

```text
A
→ B
→ ResultRouter
   ├─ C → Continue → ResultRouter
   ├─ D → Octopus → E
   └─ E → Finish
```

这展示了一个核心规则：

> 不要根据人工印象假设状态转移，实机动作后必须重新观察。

---

## 4. 循环语义

MaaFramework 节点 `repeat` 只能重复当前动作，不能直接表达“完整子流程重复 N 次”。

因此为“开贝壳次数”增加最小轮次计数逻辑。

计数点：

```text
点击“太好了”
→ 再次 OCR 确认“立即开始”
→ completed += 1
```

只有完整闭环才计数。

推荐状态：

```text
completed
target_count
task_id
```

使用 `task_id` 保证新任务启动后计数不会继承上一次运行。

---

## 5. 视觉 variant：结算页

之后发现“五个贝壳全部顺利开完”时，结算页不是单按钮居中，而是：

```text
分享 | 太好了
```

其中“太好了”位于右侧。

实测：

```text
E_001（单按钮居中）
bbox = [505,615,270,65]

E_002_share（双按钮右侧）
bbox = [720,620,270,65]
```

旧 ROI：

```text
[450,570,380,130]
```

漏掉右侧变体。

修正 ROI：

```text
[400,550,650,160]
```

两个页面业务上都只是“点击太好了”，因此没有新增两个 Finish 节点，而是记录为同一状态的两个 `variants`。

---

## 6. OCR 分框 Bug：章鱼按钮

视觉文案：

```text
保留一个随机奖品
```

但实机 PP-OCR 返回：

```json
[
  {"text":"保留","box":[338,631,60,31],"score":0.999890},
  {"text":"一个随机奖品","box":[384,631,176,31],"score":0.998196}
]
```

原配置：

```text
expected = 保留一个随机奖品
```

无法命中任何单一 OCR box。

最终更合理的配置：

```text
expected = 随机奖品
```

原因：

- 完整文案合并时可以命中；
- 被拆为“一个随机奖品”时也能命中；
- 比单独“奖品”更有区分度；
- ROI 已限定在左侧按钮区域。

这说明：

> OCR expected 应匹配单个文本框中的稳定最小语义片段，而不是机械抄完整 UI 文案。

---

## 7. 失败截图上送

本地执行 Agent 曾把现场截图保存在：

```text
client_avalonia/debug/on_error/...
```

远端模型无法直接读取本地路径。

随后验证了自动把模拟器截图注入聊天：

```text
DataTransfer File 自动化挂载
```

远端模型可以直接看见截图内容。

因此现场 Bug 工作流调整为：

```text
保存本地原始证据
+
把关键现场图直接注入对话
+
附失败节点 / 预期 / 实际 / 日志摘要
```

---

## 8. 这个案例最终验证出的开发原则

1. 用户定义业务语义，Agent 不猜“一次”是什么。
2. 动作后重新观察，不根据旧截图猜转移。
3. 一个业务状态可以有多个 visual variants。
4. 同业务状态优先扩通用识别，不为布局差异乱增节点。
5. OCR expected 要考虑分词边界。
6. 失败先采现场，再局部修改。
7. 开发测试先 N=1 / N=2，不要上来就 200 次。
8. 本地截图路径不可见时，应把图片本体自动注入远端对话。
